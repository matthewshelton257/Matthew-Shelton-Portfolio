# FocusFlow · A plan that leaves room for real life

**Speculative writing exercise for the fictional FocusFlow product used in AI Lifecycle Studio. AI-generated copy and rationale prepared at Matthew Shelton's direction. Not shipped work and not evidence of conversion results or sole human authorship.**

## The brief

**Audience hypothesis:** independent professionals with tasks scattered across notes and lists.

**Writing challenge:** explain a daily planning tool without promising that software will eliminate procrastination or guarantee productivity.

**Fictional capabilities:** create a daily plan, mark tasks complete and move unfinished tasks to a later date. The interface states below are proposed.

**Desired action:** create a first daily plan, followed by meaningful use of that plan.

## 01 · Landing page

**Eyebrow:** A little direction for your day

> # Give today a place to start.
>
> Make a daily plan, choose a task and mark it complete. When plans change, move unfinished work to a date that fits.
>
> **Create my daily plan**

### Put today in view.

Add the tasks you want to work on. Choose where to begin.

### Mark the work you've done.

Complete a task and return to your plan for the next one.

### Leave room for a different day.

Keep unfinished tasks in view without keeping them on today's list. Move them to a later date and decide what matters now.

**Closing copy:** Your day can change. Your plan can too.  
**CTA:** Create my daily plan

**Alternate headline:** Today's tasks. One place to start.

**Proposed test:** hold the body and CTA constant and vary only the headline. Compare first-plan creation per eligible visitor, with subsequent task completion as a supporting measure. Neither headline has been tested.

**Editorial rationale:** the selected route brings warmth to a practical action. The alternative makes the category clearer. Both stay within the brief; neither claims time saved or fewer decisions.

## 02 · Onboarding and interface copy

| Moment | Selected copy | Action |
| :--- | :--- | :--- |
| Welcome | What matters today? Add a task to start your daily plan. | Add a task |
| Empty plan | Your day starts here. Add the first task you want to work on. | Add a task |
| Task field | Task name | None |
| Placeholder | e.g. Draft the project outline | None |
| Empty-name error | Add a task name to continue. | None |
| Save error | We couldn't save this task. Try again. | Try again |
| First completion | One task complete. What's next? | View my plan |
| Move-task prompt | When would you like to work on this? | Move task |
| Successful move | Task moved to [saved date]. | View my plan |

**Voice decision:** encouragement belongs in welcome and completion states. Errors need a clear repair action. Dates must come from saved state, not optimistic assumptions.

## 03 · Feature-announcement email

**Scenario:** fictional launch of the ability to move a task to a later date.

**Subject:** Plans changed? Move the task.  
**Preheader:** Give unfinished work a date that fits.

> **A different day is still a plan.**
>
> Some tasks need more time. Move unfinished work to a later date, then choose what belongs on today's plan.
>
> Open a task, choose **Move task** and select a date.
>
> **Review my plan**

**Audience:** existing users with a daily plan and appropriate email consent.

**Decision:** the body explains the feature in three sentences. It avoids telling the reader they are behind.

**Proposed measure:** later completion of moved tasks among eligible accounts assigned to receive the message versus a holdout. Track unsubscribes. A click or a rescheduled task alone would not prove user value.

## 04 · Return email

**Scenario:** an opted-in user has created a plan but has not returned for seven days. Trigger timing is hypothetical and must be tested.

**Subject:** What's on your list today?  
**Preheader:** Start with what matters now.

> **A new day. A fresh decision.**
>
> Open your plan and choose one task for today.
>
> If something belongs on another day, move it to a later date. Your plan can meet you where you are now.
>
> **Open my plan**

**Decision:** no invented streak, deadline or guilt. The message invites a useful action and does not claim to know why someone stopped using the product.

**Suppression:** stop the message if the user returns before send time. Verify the destination and preferences before any implementation.

## 05 · Paid-social variants

**Starting route**  
**Headline:** Start with one task.  
**Body:** Build a daily plan and choose where to begin. Move unfinished work when your day changes.  
**CTA:** Create my daily plan

**Flexibility route**  
**Headline:** Your plan can change.  
**Body:** Give unfinished tasks a later date and choose what belongs on today's list.  
**CTA:** Create my daily plan

These are distinct audience hypotheses, not proven segments. A future test would compare completed first plans per acquisition cost and examine subsequent use.

## 06 · Voice and review notes

Use “daily plan” for the main view, “task” for the unit of work and “move” for changing its date. Keep the tone calm and practical. Avoid streak pressure, time-saving claims and invented urgency.

All email examples omit production sender and footer details. Those require real company information, preference links and channel review before deployment.
